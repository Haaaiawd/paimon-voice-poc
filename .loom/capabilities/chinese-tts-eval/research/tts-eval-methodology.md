# TTS 评估方法论：赛马怎么赛

Source: 项目文档 06_MVP_AND_EVALUATION.md §6 + 语音 agent 工程实践

评估纪律（doc 06 已定）：同一组句子打所有 provider；记录 TTFA、中文自然度、情绪、
短句/长句表现、取消速度、稳定性；不看官网 benchmark，用真实对话体验决定。

专家式补充：
- 测句集要覆盖目标域——本项目是"派蒙式短句吐槽"，所以 1–2 句口语、语气词、反问句
  必须占大头，长新闻稿式句子权重低；
- TTFA 要在真实管线里测（LLM token → chunker → TTS → 播放），单独 ping API 的数字会乐观；
- 取消语义是 barge-in 的硬依赖：cancel 后服务端是否还可能推已生成音频？本地 buffer
  谁来清？这两项要在 adapter 测试里实测，不能假设；
- 情绪控制（emotion tag → 实际语气）各家能力差异大，结构化输出的 emotion 字段
  到 TTS 参数的映射要逐个 provider 标定；
- "取消后立刻重开一句"的连续场景要测——互怼用例 G 会连续触发。

失败信号：单句 demo 很好听但连续对话中延迟漂移、取消后偶发残音、情绪标签被静默忽略。
